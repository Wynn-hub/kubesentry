## 简介

### 目的

补齐两个已确认但当前产品模型不完整的能力：在线成员集群由平台下发任务后自卸载，以及策略组、豁免策略直接配置其作用集群。两项能力均保留现有网关与成员 Operator 的 gRPC 长连接为唯一跨集群通道。

### 术语定义

| 简称/术语 | 说明 |
| --- | --- |
| 在线自卸载 | 平台向 Online 成员集群下发任务，由成员端清理 KubeSentry 自身资源的过程。 |
| 卸载任务 | 具备持久状态、可重试和结果记录的集群操作任务。 |
| 作用范围 | 策略组或豁免策略应下发到的集群集合。 |
| 内部下发记录 | 平台自动维护的 `PolicyDistribution`；不作为用户可见或可编辑的业务对象。 |

## 系统概述

### 系统目标

1. 在线集群可从平台发起卸载，操作经二次确认，成员组件自行清理 KubeSentry 资源但绝不删除命名空间。
2. 卸载后保留集群记录并显示 `Uninstalled` 状态、任务结果和审计信息；永久删除必须由独立“删除”操作触发。
3. 策略组和豁免策略在自身创建/编辑页直接选择作用集群；用户不再配置独立的“策略下发”对象。
4. 内置 `default` 策略组固定作用于全部集群，范围不可修改，仅允许启停。

### 设计约束

- Gateway/console 不持有成员集群 CRD；跨集群操作只能通过现有 `gatewaypb.Hub` 长连接完成。
- 成员端不能假定安装 Helm，卸载逻辑须使用 Kubernetes API，且必须幂等。
- 不能删除 `kubesentry-system` 命名空间，因其可能同时承载中台组件。
- CRD 是集群级高风险资源；清理范围限定为 KubeSentry 已知 CRD 名称及该 release 管理的资源。
- 现有 `PolicyDistribution` 渲染、推送和状态追踪链路必须复用，不再暴露为用户业务模型。

### 设计思路

选择“隐藏的内部下发记录”方案：策略组和豁免策略拥有直接的范围输入体验，后端自动创建或更新一个受系统管理的下发记录。相较于要求用户再进入策略下发页面，此方案不改变成熟的网关渲染通道，同时移除两步配置的心智负担。

在线自卸载采用持久化任务而非瞬时 `Dispatch`。任务会作为成员集群所需状态的一部分重送，因此在确认接收前断线不会丢失命令；成员端的清理动作可安全重试。

### 系统总体架构

```text
Console UI ── REST ──> console-api ──> PostgreSQL
                               │              │
                               │ NotifyChange │ task / internal distributions
                               v              v
                         Gateway desired-state renderer
                               │
                       gRPC Sync long connection
                               │
                      Member Operator / uninstall runner
                               │
                         Kubernetes API (member cluster)
```

策略范围保存时，console-api 写业务对象与其内部下发记录，并通知网关。网关为每个成员集群渲染匹配的策略组、豁免策略和待执行任务。成员端接收卸载任务后执行限定资源清理并回报状态。

## 功能设计

### 模块设计

| 模块 | 职责 |
| --- | --- |
| 集群管理 UI/API | 发起、查询和重试卸载任务；展示 `Uninstalling`、`Uninstalled`、`UninstallFailed`。 |
| 网关任务通道 | 将持久化任务纳入指定集群的 desired state，接收确认、进度和最终结果。 |
| 成员卸载执行器 | 按允许清单、依赖顺序、幂等地删除 KubeSentry 资源并回报。 |
| 策略组/豁免策略 UI/API | 在对象表单中验证并保存目标集群范围。 |
| 内部下发服务 | 为每个业务对象维护托管 `PolicyDistribution`，供既有渲染器使用。 |

### 集群在线自卸载

#### 状态机与确认

仅 `Online` 集群可发起卸载。危险操作弹窗要求操作者输入集群名称进行二次确认。确认后平台创建任务并把集群置为 `Uninstalling`：

```text
Online -> Uninstalling -> Uninstalled
                    \-> UninstallFailed -> Uninstalling (retry)
```

平台不因卸载成功删除集群记录。`Uninstalled` 记录保留任务开始/结束时间、执行结果和失败原因；只有用户后续点击删除，才允许永久移除记录。

#### 下发、回报与重试

- 卸载任务持久化并绑定一个集群；成员 Operator 连接或重连时持续获得未确认或执行中的任务。
- 成员端先回报“已接收”，再开始清理。平台在任务完成前保持 `Uninstalling`。
- 成员端回报成功后，平台标为 `Uninstalled`；回报失败或超时则标为 `UninstallFailed`，保留可见错误和重试入口。
- 重试使用同一幂等清理逻辑，不能因资源已不存在而失败。

#### 成员端清理范围与顺序

执行器不调用 Helm。它只通过 Kubernetes API 删除明确允许的 KubeSentry 资源，并按以下顺序处理：

1. 删除 ValidatingWebhookConfiguration，先解除准入拦截；
2. 删除 KubeSentry 管理的 Policy、PolicyGroup、PolicyException 和 PolicyVersion CR；
3. 删除 webhook/operator 工作负载、Service、TLS Secret 等命名空间资源；
4. 删除 KubeSentry 的 Role/RoleBinding 或 ClusterRole/ClusterRoleBinding、ServiceAccount；
5. 删除 KubeSentry CRD；
6. 最后删除 Operator 自身及剩余身份资源。

资源定位必须使用已知资源名和 KubeSentry Helm 标签的交集，不能依据宽泛标签或名称前缀删除其他工作负载。任何路径都不得删除命名空间。最终回报前保留最小通信身份；平台以最终成功回报作为卸载完成依据。

### 策略直接配置作用范围

#### 范围语义

- 非内置策略组与每条豁免策略必须选择“全部集群”或至少一个指定集群，空范围不能保存。
- “全部集群”动态匹配当前及未来变为 Online 的全部未卸载集群。
- “指定集群”保留选定集群绑定；目标暂时离线时不丢失，恢复在线后接收最新快照。
- 已卸载集群不可选择，也不匹配“全部集群”。
- `default` 策略组固定为“全部集群”。编辑 API 拒绝修改其范围，页面隐藏范围控件，仅允许启停及现有允许的内容编辑。

#### 内部下发映射

每个策略组或豁免策略对应一条由系统管理的内部 `PolicyDistribution`。记录包含不可变的归属类型、归属名称、范围模式和目标集群；用户无法直接增删改这些记录。

为支持豁免策略，内部下发模型扩展受控的豁免引用集合。网关渲染一个集群时，匹配其内部下发记录，汇总引用的策略组与豁免策略，随后沿用既有“最严格规则优先”的合并规则生成单一 desired-state 快照。

现有用户可见的分发 REST 路由、导航和页面会移除。历史分发记录迁移为托管映射：能唯一映射到单一策略组或豁免策略范围的记录自动收敛；不能无损映射的多对象记录在迁移报告中明确标记，不静默扩大或缩小范围。

### 接口设计

新增或调整的 REST 资源如下，具体字段在实施计划中与既有响应 envelope 对齐：

```text
POST /api/v1/clusters/{name}/uninstall
GET  /api/v1/clusters/{name}/uninstall-tasks
POST /api/v1/clusters/{name}/uninstall-tasks/{taskID}/retry
```

策略组和豁免策略既有创建、更新、详情接口增加范围字段。`/api/v1/distributions` 不再作为前端公开接口；内部服务仅由策略组/豁免策略写路径调用。gRPC 协议新增面向目标集群的卸载任务、确认、结果和错误回传字段，且所有消息继续使用现有集群长期认证令牌。

### 界面设计

- 集群详情：Online 时显示“卸载集群”；弹窗说明不会删除命名空间，要求输入名称；展示任务状态、时间、失败原因和重试。
- 策略组与豁免策略：表单新增“作用集群”区域，提供“全部集群”开关和在线/可恢复目标的多选；列表和详情展示简要范围。
- `default` 策略组：范围展示为“全部集群（内置）”，没有可编辑控件。
- 移除“策略下发”侧边栏、路由、列表与表单。

## 数据库设计

新增卸载任务表，至少包含：任务 ID、集群 ID、状态、请求时间、接收时间、完成时间、错误信息、重试次数和审计元数据。集群表增加能表达 `Uninstalling` 与 `Uninstalled` 的状态值及必要的最后一次卸载任务关联。

内部下发记录增加归属元数据和豁免策略引用，使其可由业务对象确定性地创建、更新和删除。策略组和豁免策略请求/响应携带范围；范围的权威数据由内部下发服务统一维护，避免业务对象与分发记录漂移。

迁移顺序为：先增加新表/字段与兼容读取，再迁移可无损映射的现有分发数据，最后下线公开 Distribution UI/API。迁移在单个事务边界内处理每个对象；失败记录保留并输出明确诊断，不删除原始数据。

## 非功能设计

### 可靠性

卸载任务和范围变更均持久化。网关重启、成员重连、资源已被手工删除等情况必须可恢复；资源不存在视为清理成功。任务状态写入采用与既有更新一致的并发控制，防止重复完成或过期回报覆盖新一次重试。

### 安全性

卸载属于高危操作：仅 Online 集群允许创建、UI 强制二次确认、成员端仅接受认证连接上的目标任务。RBAC 最小化到明确资源和动词；清理器使用资源 allowlist，永不删除命名空间，且不接受任意资源名称或命令作为平台输入。

### 升级/补丁

成员 Operator 与 Gateway 必须在发布同一协议版本后才启用在线卸载按钮。旧成员端不支持任务时，平台明确显示“不支持此操作”，不伪造任务成功。数据库迁移必须先于新 API 与渲染逻辑部署。

### 运维设计

任务列表和集群详情提供可读错误；Operator 日志记录任务 ID、资源种类和结果，但不得记录认证令牌。支持从 `UninstallFailed` 进行显式重试，不做无限自动重试。

### 兼容性

已有“全部集群”默认基线保持覆盖语义。下发链路继续使用现有 gRPC Sync 和 `PolicyDistribution` 渲染机制；只有用户可见的配置入口从独立分发页面迁移到策略组/豁免策略页面。

## 验证计划

- 后端单元/集成测试：范围必填、`default` 范围不可改、全量/指定匹配、豁免随范围下发、迁移结果与历史异常诊断。
- 任务测试：状态机、重复请求、成员重连、确认/完成/失败回报、失败重试和权限拒绝。
- 成员端测试：使用 fake Kubernetes client 验证清理顺序、allowlist、CRD 清理、资源已不存在的幂等性，以及不删除命名空间。
- 前端测试与构建：卸载二次确认、状态展示、范围必填、`default` 只可启停；运行 `vue-tsc --noEmit`、前端测试和生产构建。
- 端到端测试：在线成员接收卸载任务、完成资源清理、平台标为 `Uninstalled`；新上线成员自动接收“全部集群”范围的策略与豁免。
