# KubeSentry Console 导航、概览统计与分页能力概要设计

日期：2026-07-22  
分支：`feat/console-redesign`  
状态：已完成交互评审，待文档评审

# 简介

## 目的

本文定义 KubeSentry Console 的一组基础体验改进：平台概览使用真实集群统计数据，侧边栏品牌入口返回首页，详情/新建/编辑等二级页面提供可靠的返回能力，以及所有业务数据集合具备一致的分页体验。

当前平台概览将集群数量硬编码为 `1`；品牌区域不可点击；各详情页分别直接调用 `router.back()`，无法处理直接访问深层 URL 的场景；全部列表接口一次性返回完整数组，页面分页、排序与筛选状态也无法通过 URL 恢复。本文给出前后端协同设计，以统一这些行为。

## 术语定义

| 简称/术语 | 说明 |
| --- | --- |
| 主列表 | 策略、策略组、例外、策略分发、集群及安装记录等通过独立 API 加载的数据列表 |
| 嵌套集合 | 平台概览、详情页或表单内部随页面数据一起加载的业务集合 |
| 服务端分页 | 服务端针对完整候选数据完成筛选、排序并只返回当前页 |
| 前端分页 | 前端已持有完整集合，在浏览器内排序、切片并展示当前页 |
| 父级回退 | 当前页面没有有效站内历史时使用的确定性返回目标 |
| 分页状态 | 页码、每页数量、排序和筛选等可序列化到 URL 的列表状态 |

# 系统概述

## 系统目标

本次设计满足以下需求：

| 需求编号 | 需求 |
| --- | --- |
| REQ-OVERVIEW-001 | 平台概览的集群总数必须来自数据库中的已注册集群，而不是硬编码值 |
| REQ-OVERVIEW-002 | 集群卡展示 `Online`、`Offline`、`Registering` 三种状态数量，零值状态可隐藏 |
| REQ-NAV-001 | 点击侧边栏 KubeSentry 图标或文字返回平台概览 |
| REQ-NAV-002 | 详情、新建、编辑和规划中页面提供返回按钮；优先返回上一站内页面，无历史时回到父列表 |
| REQ-PAGE-001 | 策略、策略组、例外、策略分发、集群、安装记录采用服务端分页 |
| REQ-PAGE-002 | 平台概览集合、策略组详情集合、版本历史、策略组表单已选项采用前端分页 |
| REQ-PAGE-003 | 默认每页 20 条，可选择 10、20、50、100 条 |
| REQ-PAGE-004 | 主列表的排序必须作用于完整候选数据集，而不是仅排序当前页 |
| REQ-STATE-001 | 分页、排序、筛选和标签页状态写入 URL，刷新、返回和分享 URL 后均可恢复 |

成功标准：

1. 首页集群总数与集群管理列表的总记录数一致，状态计数之和与已知状态下的总数一致。
2. 从任意带筛选和分页状态的主列表进入二级页面后，点击返回可恢复原 URL 和页面状态。
3. 直接打开二级页面 URL 时，返回按钮进入正确父列表，而不是离开应用或无响应。
4. 主列表接口最多返回请求页大小的数据，响应同时包含完整候选结果的总数。
5. 所有已确认的业务集合在超过一页时均可翻页，数据不足一页时不显示冗余分页控件。

## 设计约束

- 继续使用 Vue 3、TypeScript、vue-router、vue-i18n、Element Plus 和现有 Axios 请求层。
- 后端继续使用 Go `net/http`、GORM 与 PostgreSQL；不引入新的数据库表或外部组件。
- 保持现有 `/api/v1` 路径和 `success/data/error` 响应信封。
- 主列表采用服务端分页；嵌套集合采用前端分页，不为嵌套集合拆分新子资源接口。
- URL 是列表浏览状态的事实来源；默认页大小固定为 20，不随窗口尺寸自动变化。
- 排序字段必须经过服务端白名单映射，禁止将客户端字段名直接拼接到 SQL。
- `pageSize` 最大为 100；默认排序必须稳定，防止跨页重复或遗漏。
- 不改变鉴权模型、数据库结构、Kubernetes 部署结构或业务对象语义。
- 当前工作区已有平台概览 API 契约修复，实施时必须保留并在其基础上扩展，不得覆盖或回退。

## 设计思路

评审过以下三种方案：

1. **统一分页协议并分层处理（采用）**：主列表统一服务端协议，嵌套集合使用公共前端分页能力，导航与 URL 状态抽为共享组件和组合式函数。
2. **每页独立实现（未采用）**：短期直接，但会复制查询参数、URL 同步、错误处理和分页栏代码，长期行为容易分叉。
3. **所有集合服务端分页（未采用）**：扩展性最强，但需要为策略组成员、排除成员和版本历史增加独立 API，超出当前规模与目标。

采用方案将职责分为四层：

- API 契约层：统一分页请求和响应。
- 服务端查询层：在完整候选结果上筛选、排序、计数和切页。
- 前端状态层：URL 查询参数解析、规范化与请求竞态保护。
- 展示层：统一分页栏、返回按钮和品牌首页入口。

## 系统总体架构

```text
用户操作
  │
  ├─ 品牌/返回按钮 ──> vue-router ──> 历史记录或父级回退
  │
  └─ 筛选/排序/分页
          │
          v
  URL 查询参数（页面状态事实来源）
          │
          ├─ 主列表 ──> /api/v1/*?page=&pageSize=&sortBy=&sortOrder=
          │                  │
          │                  v
          │            handler 参数校验
          │                  │
          │                  v
          │            repository/派生字段计算
          │                  │
          │                  v
          │            PageResult<T>
          │
          └─ 嵌套集合 ──> 浏览器内稳定排序和切片
```

平台概览统计数据流：

```text
clusters 表 ──> ClusterRepo 聚合统计 ──> GET /api/v1/summary
                                              │
                                              v
                    totals.clusters + clusterPhases
                                              │
                                              v
                                   OverviewView 集群卡
```

## 系统运行环境

- 浏览器：当前项目支持的现代 Chrome/Chromium 环境。
- 前端运行时：nginx 提供 Vue SPA，通过同 Pod localhost 代理 `/api/v1`。
- 后端：`cmd/console` API 容器。
- 数据库：PostgreSQL，沿用 `internal/dbrepo` GORM 仓储。
- 本地验证：`kubesentry-system` 命名空间中的 Kubernetes 部署。

## 模块设计

| 模块 | 职责 | 主要依赖 |

## 模块设计详细描述

### 1. 集群汇总统计

`GET /api/v1/summary` 增加集群仓储依赖，返回：

```json
{
  "totals": {
    "clusters": 12,
    "policies": 37,
    "policygroups": 3,
    "exceptions": 2
  },
  "clusterPhases": {
    "online": 9,
    "offline": 2,
    "registering": 1
  },
  "groups": []
}
```

`totals.clusters` 使用独立总数统计；三个状态按数据库 `phase` 聚合。总数不能通过硬编码或仅对当前列表页计数得到。前端 `normalizeSummary` 同步验证新增字段，缺失或类型错误时拒绝渲染，避免以伪造的零值掩盖契约漂移。

首页集群卡：

- 主数字展示 `totals.clusters`。
- 次要信息依次展示在线、离线、注册中数量；对应数量为零时隐藏该状态。
- 卡片具备 `role="button"`、键盘焦点和 Enter 激活能力。
- 点击进入 `/clusters`。

### 2. 服务端分页协议

主列表统一接收：

| 参数 | 类型 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `page` | 正整数 | `1` | 必须大于等于 1 |
| `pageSize` | 正整数 | `20` | 仅允许 10、20、50、100 |
| `sortBy` | 字符串 | 各资源默认字段 | 必须属于资源排序白名单 |
| `sortOrder` | 字符串 | `asc` 或资源默认值 | 仅允许 `asc`、`desc` |

统一响应数据：

```json
{
  "items": [],
  "total": 128,
  "page": 2,
  "pageSize": 20
}
```

服务端处理顺序固定为：参数校验 → 筛选 → 完整候选集排序 → 统计 `total` → 切页 → DTO 转换。页码超出最后一页不是协议错误，返回空 `items` 和正确 `total`，由前端规范化到最后一个有效页。

普通数据库字段应通过 GORM 条件、`COUNT`、`ORDER BY`、`LIMIT` 和 `OFFSET` 下推到 PostgreSQL。依赖运行时解析的派生字段，例如策略组 `resolvedCount`，允许服务端加载候选集合、完成派生计算后再稳定排序和切页；无论执行位置如何，排序必须覆盖完整候选集。

所有排序使用稳定次级键：名称型资源以 `name ASC` 为次级键；安装记录以唯一 ID 为次级键。各 handler 将 API 字段映射到固定查询表达式，不接受任意 SQL 标识符。

### 3. 主列表范围与默认排序

| 页面/接口 | 服务端分页 | 默认排序 | 可排序字段 |
| --- | --- | --- | --- |
| 策略 `/policies` | 是 | `name asc` | name、source、enforcementMode、phase、createdAt、updatedAt |
| 策略组 `/policygroups` | 是 | `name asc` | name、displayName、enabled、phase、resolvedCount |
| 例外 `/exceptions` | 是 | `name asc` | name、phase、targetSummary、duration、expiresAt |
| 策略分发 `/distributions` | 是 | `name asc` | name |
| 集群 `/clusters` | 是 | `name asc` | name、phase、operatorVersion、lastHeartbeatAt、createdAt |
| 安装记录 `/install-records` | 是 | `createdAt desc` | clusterName、namespace、createdAt |

策略页已有 source、phase、mode、keyword 筛选全部在分页前执行。后续页面新增筛选时沿用同一规则：筛选参数属于 URL 状态，筛选变化将页码重置为 1。

### 4. URL 状态管理

共享组合式函数负责：

1. 从 `route.query` 解析分页、排序和筛选状态。
2. 对非法或缺失值使用默认值，并通过 `router.replace` 将 URL 规范化。
3. 用户改变筛选、排序、页码或每页数量时更新当前历史记录。
4. 筛选、排序或每页数量变化时将页码重置为 1。
5. 生成 API 查询参数。

使用 `router.replace` 可避免浏览器后退逐次回放用户的每次筛选操作；点击详情链接仍使用正常 push 导航，因此返回历史时恢复完整列表 URL。

单列表页面使用 `page`、`pageSize`、`sortBy`、`sortOrder`。多集合页面使用明确前缀：

| 页面 | 查询参数前缀 |
| --- | --- |
| 集群列表标签 | `clusters*` |
| 安装记录标签 | `records*` |
| 概览策略组健康 | `overviewGroups*` |
| 概览需要关注 | `overviewAttention*` |
| 策略组生效成员 | `members*` |
| 策略组排除成员 | `excluded*` |
| 策略版本历史 | `versions*` |
| 策略组表单已选项 | `selected*` |

集群管理当前标签页使用 `tab=clusters|records`，同样写入 URL。

### 5. 请求生命周期

- 每次加载生成递增请求序号；只有最后一次请求可以更新列表和 loading 状态。
- 请求失败时保留已有成功数据和 URL 状态，并显示错误消息。
- 删除或状态切换成功后重新加载当前页。
- 删除当前页最后一项导致页码超界时，计算最后一个有效页，更新 URL 并重新请求。
- 页面卸载后不再写入组件状态。

该机制不要求立即引入新的取消请求依赖；序号保护足以阻止旧响应覆盖新响应。未来可以在请求层补充 `AbortController`，但不属于本次范围。

### 6. 嵌套集合分页

以下集合由前端对已加载完整数组进行分页：

- 平台概览：策略组健康、需要关注。
- 策略组详情：生效成员、排除成员。
- 策略详情：版本历史。
- 策略组新建/编辑：已选策略表格。

公共客户端分页逻辑接收完整数组、分页状态和可选稳定比较器，返回当前页、总数和校正后的有效页。业务选择状态与显示页分离，例如策略组表单翻页不能改变未显示策略的勾选结果。

动态规则行、标签编辑行、资源条件行、固定枚举和下拉框选项属于编辑控件，不显示分页栏。需要完整策略、策略组或集群候选项的表单，通过 `collectAllPages` 按最大页大小逐页获取并合并，直至收集数量达到 `total`；该适配避免分页 API 使现有选项静默截断。

### 7. 分页展示组件

统一分页栏展示：

- 左侧：“共 N 条”。
- 右侧：每页数量选择器、上一页、页码、下一页。
- 可选页大小：10、20、50、100；默认 20。
- 仅一页或无数据时隐藏分页操作，但空状态仍清晰展示。
- 表格区域适配可用宽度和高度，页大小不随窗口缩放自动改变。

Element Plus 表格使用受控排序模式。列头排序事件只更新 URL/请求状态，禁止继续使用仅针对当前页的本地默认排序。嵌套集合若提供排序，也必须先排序完整数组再切页。

### 8. 返回导航

路由为所有详情、新建、编辑和规划中页面声明父级回退路径。返回操作：

1. 如果 Vue Router 写入的 `window.history.state.back` 是当前 router base 下的非空应用路径且不等于当前路径，则视为有效站内上一页并调用 `router.back()`；不使用不可靠的 `window.history.length` 推断。
2. 如果用户直接打开深层 URL 或上一页不是有效站内位置，导航到 route meta 中的父级回退路径。

静态父级在 route meta 中保存命名路由；编辑页等动态父级保存路由名称并复用当前 `name` 参数，由共享导航函数调用 `router.resolve` 生成目标。这样 fallback 不依赖字符串替换，也不会把用户带到应用外部。

示例：

| 页面 | 父级回退 |
| --- | --- |
| 策略详情/新建 | `/policies` |
| 策略编辑 | `/policies/:name`，无法生成详情目标时回 `/policies` |
| 策略组详情/新建 | `/policygroups` |
| 策略组编辑 | `/policygroups/:name`，无法生成详情目标时回 `/policygroups` |
| 例外新建/编辑 | `/exceptions` |
| 策略分发新建/编辑 | `/distributions` |
| 集群详情 | `/clusters` |
| 规划中页面 | `/` |

`PageHeader` 提供可选返回区域并复用共享导航函数。平台概览、五个主列表页面和集群安装记录标签不显示返回按钮。已有详情页中散落的 `$router.back()` 被统一组件取代。

### 9. 品牌首页入口

`AppLayout` 中品牌图标和 KubeSentry 文本包装为一个 `router-link`，目标为 `/`。保留现有视觉样式，补充 hover、focus-visible 和键盘操作状态。点击品牌使用正常应用内导航，不强制刷新页面。

## 接口设计

### 分页类型

前端公共类型：

```ts
interface PageResult<T> {
  items: T[]
  total: number
  page: number
  pageSize: number
}
```

后端使用等价泛型或明确 DTO；外层仍为：

```json
{
  "success": true,
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "pageSize": 20
  },
  "error": null
}
```

### 错误响应

参数错误沿用现有信封，例如：

```json
{
  "success": false,
  "data": null,
  "error": "invalid sortBy for policies"
}
```

HTTP 状态为 400。数据库、解析或聚合失败保持 500。错误信息不得包含 SQL、凭据或数据库连接详情。

### API 兼容影响

上述六个列表端点的 `data` 从数组变为 `PageResult`，属于 Console 内部 API 契约调整。SPA 与 API 位于同一 Console Pod 并随同一版本交付，所有仓库内调用点、handler 测试及 e2e 测试必须在同一变更中升级。不更改单项详情、创建、更新和删除端点。

```text
┌────────────────────────────┐
│ 集群                       │
│ 12                         │
│ 在线 9 · 离线 2 · 注册中 1 │
└────────────────────────────┘
```

```text

```

返回按钮位于页面标题左侧或标题区首位，主操作按钮仍位于右侧。品牌图标和文字形成一个整体点击区域，不改变侧边栏信息架构。

# 数据库设计

本次不增加或修改数据库表、索引和迁移。分页使用现有表字段。实施阶段若查询计划显示常用排序字段缺少索引，应另行记录性能证据并单独评审索引变更，不在本设计中预设迁移。

# 非功能设计

## 性能

- 单次主列表响应最多包含 100 条记录。
- 普通字段的筛选、排序、计数和分页优先下推数据库。
- `collectAllPages` 使用每页 100 条并串行终止于 `total`，仅用于确实要求完整候选项的编辑表单。
- 派生字段分页必须优先保证全量排序正确性；若未来数据规模导致内存计算成为瓶颈，再设计物化状态或专用查询，不在本次提前引入。
- 概览集群状态使用聚合查询，不读取完整集群详情到前端。

## 可靠性

- 稳定次级排序避免翻页过程中的重复和遗漏。
- 请求序号保护避免竞态响应覆盖。
- 删除后自动修正超界页。
- 汇总失败时明确报错，不以硬编码或零值冒充真实统计。

## 安全性

- 所有分页数值进行范围校验。
- 排序字段和方向均使用白名单映射，禁止 SQL 字段注入。
- 筛选继续使用 GORM 参数绑定。
- URL 不保存令牌、安装命令或其他秘密，只保存列表浏览状态。
- 不扩大 Kubernetes RBAC、数据库权限或网络访问范围。

## 升级/补丁

前后端分页契约必须作为一个版本发布。因为 web 与 api 容器同属 Console Deployment，升级时由新 Pod 同时承载匹配版本；不得只部署新 web 镜像而保留旧 API 契约。回滚同样应回滚整个 Console 版本。

## 容灾设计

不适用。本次不引入持久状态或新服务；浏览状态保存在 URL，数据库仍使用现有容灾方案。

## 安装部署

不修改 Helm 资源结构。实施完成后重新构建 Console API 与 Console Web 镜像，部署到本地 `kubesentry-system` 命名空间进行验证。使用本地不可拉取镜像时应使用唯一镜像标签，避免 `imagePullPolicy: Never` 复用旧标签缓存。

## 运维设计

- 可通过浏览器 URL 直接复现特定筛选、排序和分页状态，便于问题排查。
- API 参数错误返回 400，数据库错误返回 500，可通过现有容器日志定位。
- 不新增指标和日志系统；如后续需要观测慢分页查询，应另行设计 SQL 延迟指标。

## 兼容性

- 支持当前 Vue Router history 模式和 nginx SPA fallback。
- 中英文文案同步更新。
- 直接访问旧的无查询参数列表 URL 时使用默认分页状态。
- 书签中的未知或非法查询参数不会导致页面崩溃；分页相关非法值会被规范化，非本模块参数保留。
- 不改变已有对象字段、创建更新流程、删除保护或乐观并发语义。
